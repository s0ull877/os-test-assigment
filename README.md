# Booking API

[Стек](#stack) · [Быстрый старт](#quick-start) · [Тестирование](#testing)

REST API для бронирования столика в ресторане. Тестовое задание [**ОСЬ · Backend Trainee**](https://github.com/s0ull877/os-test-assigment/blob/home/%D0%9E%D0%A1%D0%AC_%D1%82%D0%B5%D1%81%D1%82%D0%BE%D0%B2%D0%BE%D0%B5_backend_trainee%202.pdf) на Python и FastAPI.

Сервис позволяет создать бронь, получить список с фильтрацией по дате, найти бронь по ID и отменить её. Главное правило: **на одну дату и время может существовать только одна активная бронь**. Отмена сохраняет запись и освобождает слот.

## Быстрый старт

### 1. Установить [Git](https://git-scm.com/downloads) и [uv](https://docs.astral.sh/uv/getting-started/installation/)

Установка uv в Windows:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Установка uv в Linux / macOS:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

После установки откройте новый терминал и проверьте доступность команды:

```shell
uv --version
```

### 2. Клонировать репозиторий и подготовить окружение

```shell
git clone --branch master https://github.com/s0ull877/os-test-assigment.git
cd os-test-assigment
uv python install 3.13
uv sync --locked --group dev
```

`uv sync` создаёт локальное окружение `.venv` и устанавливает зависимости проекта, включая инструменты разработки и тестирования. Флаг `--locked` проверяет согласованность `pyproject.toml` и `uv.lock` без изменения lock-файла. Если они расходятся, команда завершится ошибкой.

### 3. Инициализировать базу данных

Выполните из корня репозитория:

```shell
uv run --locked alembic upgrade head
```

Команда создаёт файл `data/db.sqlite3`, таблицу бронирований и ограничения из миграций. Повторный запуск `upgrade head` применяет только ещё не выполненные миграции.

### 4. Запустить приложение

```shell
uv run app
```

| Адрес | Назначение |
| --- | --- |
| [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) | Swagger UI: описание API и отправка запросов |
| [http://127.0.0.1:8000/openapi.json](http://127.0.0.1:8000/openapi.json) | Спецификация OpenAPI |

Команда `app` зарегистрирована в `pyproject.toml` и вызывает функцию `main()` из `src.app`.

## Настройки

Для запуска с параметрами по умолчанию файл `.env` не требуется. Чтобы изменить настройки, создайте `.env` в корне проекта:

```dotenv
APP_NAME=Booking service
APP_HOST=127.0.0.1
APP_PORT=8000
DEBUG=0

DB_ENGINE=sqlite+aiosqlite
DB_NAME=db.sqlite3
```

## Тестирование

Запустите все тесты из корня репозитория:

```shell
uv run --locked --group dev pytest -q
```

`--group dev` подключает зависимости для разработки и тестирования, а `-q` включает краткий вывод результатов. Чтобы увидеть названия тестов и результат каждого из них, используйте `-v` вместо `-q`.

Запуск отдельного файла, например тестов HTTP API:

```shell
uv run --locked --group dev pytest tests/integration/test_booking_api.py -v
```

### Что проверяется

| Файл | Назначение |
| --- | --- |
| `tests/integration/test_booking_api.py` | Проверяет API через HTTP-запросы: создание, получение и отмену брони, статус-коды и сообщения ошибок, валидацию входных данных. Проверяет отказ при повторном и конкурентном бронировании одного слота, повторную отмену и возможность занять освободившийся слот. |
| `tests/integration/test_bookings_service.py` | Проверяет сервис с настоящей SQLite-базой: сохранение данных, конфликт активных броней, получение отсутствующей записи, фильтрацию по дате, повторную и конкурентную отмену. Дополнительно проверяет, что нарушение ограничения количества гостей не превращается в ошибку занятого слота. |
| `tests/integration/test_transactions.py` | Имитирует ошибку при `commit` и проверяет, что исключение передаётся вызывающему коду, транзакция завершается откатом, а несохранённая бронь отсутствует при чтении из новой сессии. |

### Фикстуры

| Файл | Назначение |
| --- | --- |
| `tests/conftest.py` | Подготавливает общие тестовые данные: опорную дату и время, DTO для создания брони и JSON-тело запроса. |
| `tests/integration/conftest.py` | Создаёт временную SQLite-базу, таблицы, сессии, сервис и HTTP-клиент. Подменяет зависимость приложения, чтобы запросы работали с тестовой базой. |

Для каждого теста создаётся отдельная временная база, поэтому рабочий файл `data/db.sqlite3` не используется. Запускать сервер через `uv run app` или применять миграции к рабочей базе перед тестированием не требуется: HTTPX обращается непосредственно к ASGI-приложению, а тестовые таблицы создаются из ORM-моделей.
